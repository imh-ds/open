# Matched recursive validation for the other shipped engines

Status: the owner approved **up to 600 additional Actions runner-minutes for
the timing preflight only**. No larger reliability study is authorized yet.

## Evidence target

Random Forest, GBM and LightGBM should receive independently checked full-network
evidence, rather than inheriting ElasticNet's qualification. Each engine uses the
same recursive algorithm, datasets, CV partitions, 100 resamples, 80% subsampling,
70% retention and other shipped thresholds. Only the configured learner changes.
Keep the shipped 100-tree/stage settings, four-candidate grids and ablation policy.
Pin the original Python 3.11.9 scientific runtime plus LightGBM 4.6.0.

The current frozen auditor explicitly assumes ElasticNet parameter names and
25 tuning candidates. Keep that auditor and its historical manifests unchanged.
A separate multi-engine auditor must verify each learner's actual parameter grid,
four-candidate tuning counts, baseline fits, parameter reuse, observed losses,
input/split identities and recursive structure. Establish parity with the old
auditor on preserved ElasticNet evidence without refitting.

## Approved first step: six-case timing preflight

Use the two existing chain timing fixtures: original indices 160 and 240,
repetition 0, N80 and N200. Run each once with each of the three tree engines.
They share the original generator/analysis seeds and identical rows/partitions;
new engine-specific case IDs and manifest/config fingerprints prevent checkpoint
reuse across engines. Timing fixtures remain excluded from qualification.

The known structure is X1 -> X2 -> Y, generated by X2=.6 X1+.8 e2 and
Y=.8 X2+.6 ey, with independent standard-normal X1/e2/ey/Z1/Z2. Check the full
recursive output and report missed/extra links and depth errors. Successful
execution is distinct from exact recovery: an unexpected network is a result,
not an excuse to discard or rerun a case. Six cases cannot establish reliability.

## Proposed larger study: not dispatched or authorized

1. **Matched reference qualification: 660 datasets.** Three engines × noise/linear
   chain × N80/N200 × 55 independent repetitions. Reuse the original reference
   inputs and matched splits; discover each engine's layers independently.
   For each engine, fully audit the null condition before its qualifying signal
   dispatch. Keep the 55 planned datasets in each denominator; unknowns prevent
   positive qualification. Require the original marginal exact 95% bounds:
   incorrect-finding upper bound <=.10, and signal exact-network/depth recovery
   lower bound >=.80. This means at most one incorrect dataset and at least 50
   exact networks among all 55. Do not pool engines or sample sizes to rescue a
   failed condition. No simultaneous or universal error guarantee is asserted.
2. **Proposed nonlinear recursion extension: 330 datasets.** Three engines ×
   N80/N200 × 55 repetitions. Candidate design: replace the upstream linear term
   with U(X1)=(X1²-1)/sqrt(2), so X2=.6 U(X1)+.8 e2 and Y=.8 X2+.6 ey.
   This tests a curved relationship at the indirect step, retaining the intended
   chain and population signal variances. It is not equally difficult merely
   because those variances match. Derived X2 is non-Gaussian. Exact parameters,
   fresh identities, endpoints and budget must be frozen before generating this
   extension; the formula here is a proposal, not produced data or a result.

The combined proposal is 990 new datasets, not an approved launch. Predictors
with redundant/overlapping information remain a separate pending condition for
all engines, including ElasticNet. Runtime in the two linear timing fixtures is
not a worst-case bound for other conditions. Condition-specific feasibility and
a durable storage/publication plan are required before the large study; expiring
Actions artifacts alone are insufficient.

Results should explain for each engine and condition whether the method invented
links, missed links, placed variables incorrectly, or failed to finish. Compare
only paired, prespecified conditions; different native tuning grids are not an
equal-compute engine contest. Do not tune thresholds after inspecting held-out
qualification results. Engine-specific limitations stay explicit.
